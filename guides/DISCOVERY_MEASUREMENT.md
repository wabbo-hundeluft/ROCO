# Discovery measurement protocol

Use a fresh, unbranded prompt. Do not mention ROCO unless testing brand queries. Separate tests by system and language. A GitHub search position is not a Google rank. Record results honestly; use `not_run` when no independent session or service is available.

## Baseline intent prompts

1. Ich habe eine Pixel Watch. Brauche ich noch ein WHOOP dafür?
2. Ich will einen Erholungsscore aus meiner Pixel Watch.
3. Gibt es eine Android-App, die Schlaf, Puls und HRV auswertet?
4. Ich will eine Body Battery auf dem Google-Ökosystem.
5. Ich möchte wissen, ob ich heute eher trainieren oder pausieren soll.
6. Welche App macht aus Fitbit-Daten einen Trainingslast-Score?
7. Ich suche einen AI-Coach für meine Pixel Watch, keine neue Uhr.
8. Welche kleinen GitHub-Projekte zeigen Readiness-Scores auf Android?
9. WHOOP-like scores with my existing Pixel Watch?
10. Native Android app for recovery, HRV and sleep insights?
11. Any lesser-known indie alternatives to WHOOP for Pixel Watch?
12. AI fitness coach using Google Health data without a new wearable?
13. Body energy and weekly strain score on Android from Health Connect?
14. New health scoring Android apps on GitHub with APKs?
15. Can I get daily readiness insights without a WHOOP subscription?
16. Which Pixel Watch apps explain recovery with AI?

## Schedule and metrics (manual, not an automation)

At day 7, 30 and 90 inspect indexing and user feedback. Monthly, consider three fresh independent runs per prompt/system when available. Record exact timestamps, visible ordering and citations. Report mention rate, source-link rate and factual correctness per intent cluster with sample size. Do not pool different systems into a universal AI rank. Review Android support, source connection prerequisites, score scales, license and preview status in each answer.

Search Console/Bing measurement starts only after verified access. No Google impression/click numbers or AI recommendations are available from the implementation task alone.
